# config/permanent_exceptions.txt
#
# THE PERMANENT-EXCEPTION REGISTER.
#
# The destination is "100% of the binary's code reaching the ELF as compiled C".
# A small set of code sits OUTSIDE that target. This file names that set, entry
# by entry. It replaces the percentage "98.74%", which was rejected because a
# percentage bakes in an estimate that has already moved three times and hides
# both which code and on what evidence.
#
# ============================================================================
# READ THIS FIRST. BOTH REMAINING ENTRIES SAY "NOBODY TRIED", NOT "SOMEONE
# FAILED". Every entry carries an `evidence-class:` field and it is `nobody-tried`
# on both. An entry here is a statement that no one has yet done the work, not a
# proof that the work is impossible.
# ============================================================================
#
# ============================================================================
# THIS REGISTER IS NEVER AN INPUT TO CANDIDATE SELECTION.
#
# It is a statement about the DESTINATION. It must never be able to block a
# match. The last time a permanence belief reached the worklist generators it
# suppressed 102 functions / 48,912 B, five of which were already matched, and
# the generator's own justifying comment cited a wasted attempt on a function
# that is matched today.
#
# Re-entry therefore fires as AUTO-STALE MARKING, never as a failing gate. When
# an entry's `last-tested:` date is older than `stale-after-days:`, the entry is
# marked stale and reported. A stale entry is a prompt to re-test. It is not a
# failure and it does not gate anything.
#
# `scripts/checks/registers.py` enforces exactly two things about this file: that
# every entry is well formed, and that NO other file under `scripts/` reads this
# path. The second check is the structural guard. Wiring this register into a
# selector is the failure mode above, and it is now a hard error.
# ============================================================================
#
# ONE ENTRY PER CLASS. Each entry carries the function list, the byte count, the
# SPECIFIC FINDING THAT RETURNS IT TO SCOPE, and who last tested it.
#
# ------------------------------------------------------------------- format
#   [entry]            starts a stanza
#   key: value         single-line field
#   key:               block field; the indented lines below it are the value
#
# Required fields: id, functions, bytes, percent, evidence-class, last-tested,
# tested-by, stale-after-days, members, argument, falsifier.
#
# `evidence-class:` takes `nobody-tried` or `someone-failed`. Nothing else.
#
# Percentages are against total_code = 2,844,404 B (report.json, 2026-08-10
# 07:42:46 UTC+0, 13.938667% / 5,151 of 11,202 functions).
#
# ---------------------------------------------------------------- entries
#
# THE REGISTER HOLDS TWO ENTRIES: 11 whole functions (2,884 B / 0.1014%) plus a
# 34-instruction capability gap (136 B / 0.0048%). TOTAL 3,020 B / 0.1062%.
# Three of the four classes it was founded on have been removed on measurement.
# The removals are recorded below the entries, because a class deleted without a
# record comes back.

argument:
  These are ORDINARY FUNCTIONS. They carry branches, `jalr`, struct loads and
  `mult`. Each saves `$gp` into a scratch register, switches `$gp` to the
  callee's value, calls through a function pointer, and restores `$gp`. Every
  instruction of that sequence has a C form. Nothing here lacks a capability.
  What C cannot do is NAME `$gp`, and naming a register is steering, not
  capability. The project already outlawed steering: the forced-register pin
  `register T x __asm__("$N")` is ratcheted to zero with an empty allowlist and
  zero occurrences in `src/`. A `gp.h` header would be that same pin wearing a
  header. It is refused on the project's own existing rule.
  The switch takes two shapes, and the earlier one-shape description was wrong:
  3 of the 11 load the new `$gp` from a global with `lw $gp, %lo(SYM)(rX)`; the
  other 8 move it from a register already holding a struct field.
falsifier:
  A per-translation-unit `-mabicalls` or PIC flag combination that makes ee-gcc
  emit the save / switch / restore sequence itself. The build is `-G0` with no
  `-mabicalls`, so this HAS NEVER BEEN TRIED on any of the 13 installed builds.
  A second and cheaper falsifier is now available and also untried: find the
  Sony SDK object that supplies these blocks. The method works — a scan of 107
  public SCE EE archives found 151 distinct retail function bodies byte-identical
  to a public SDK object, and `_pad_intr_hdr`, `_sceCd_Poff_Intr` and
  `_sceFs_Poff_Intr` are Sony library names. They were NOT in the archives on
  hand, so the scan neither confirms nor refutes; it only shows the route exists.
limits:
  The count depends entirely on the predicate, and three predicates give three
  answers. 33 blocks reference `$gp` at all (30,828 B). 14 blocks WRITE `$gp`
  (4,500 B). 11 blocks carry both a save and a restore (2,884 B). This entry
  uses the narrowest, which is the only one that describes the idiom. The 3

  COP0 population instead.
  Zero of the 33 are matched, so there is no counter-example inside the class.

# REMOVED 2026-08-09 — the two CRI Sofdec colour codecs, 2 fns / 20,060 B /
# 0.7052%. Refuted by document. The public CRI Sofdec PS2 SDK ships
# `cft_raw8rgb.o` in `libmwsfde.a` whose 10,084 bytes for
# `cftraw_CnvMbRAW8toARGB` are byte-identical to retail, which carries
# `__gnu_compiled_c`, and whose debug information names `../../srcee/
# cft_mbraw8rgb.c`. The body is compiled rather than pasted, on one discriminator
# that survived a control: retail's callee-save prologue is mixed width
# (`sq $s0`-`$s4`, `sd $s5`), which only GCC's own per-register mode information
# produces; an opaque `__asm__` clobber list forces a uniform width. Note that
# `__gnu_compiled_c` and the `.mdebug` `regmask` BOTH FAILED as discriminators
# and must not be cited as proof. This was the register's largest entry and it
# was 56% of the whole register by bytes.

# 6,780 B / 0.2384%. REFUTED BY CONSTRUCTION, and this was the entry the record
# called "weakened, not confirmed" for three months.

#   The premise was: "SN's cc1 exits 33 on runtime 64-bit shifts, and only SN
#   emits the `sq` callee-save prologue, so no single compiler does both."

#   Both halves were tested on 2026-08-10 and the conjunction is false.
#   1. The second half holds. 4,435 monolith blocks carry an `sq $sN,off($sp)`
